# Отчёт о реализации

Проект: **Lingua Quest Bot** — Telegram-игра для изучения языка.
Реализация с нуля по документу `Telegram Language Learning Game — Requirements.md`.

---

## 1. Инфраструктура и конфигурация

- Создана структура проекта с нуля (Node.js + TypeScript, CommonJS/Node16).
- `package.json` со скриптами: `dev`, `build`, `start`, `typecheck`, `db:migrate`, `db:deploy`, `db:seed`, `db:studio`.
- `tsconfig.json` в строгом режиме: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`.
- `.env.example` со всеми переменными; `.gitignore` исключает `.env`, `dist`, `node_modules`.
- `railway.json`: build `npm run build`, start `npm start`, healthcheck `/health`.
- Валидация окружения через **Zod** (`src/config/env.ts`) — процесс падает при старте, а не в рантайме.
- Секреты не хранятся в коде и вырезаются из логов (`redact` в pino).
- **Тесты и vitest не используются** — по требованию удалены из зависимостей и скриптов.

## 2. Архитектура

- Строгое разделение слоёв: `Telegram handlers → Services → Prisma → PostgreSQL`.
- Ни одной игровой формулы внутри callback-обработчиков.
- Сервисы: `user`, `streak`, `economy`, `reward`, `learning`, `quest`, `achievement`, `dailyBonus`, `shop`, `personalReward`, `stats`, `easterEgg`.
- Чистые (без IO) модули для логики, которую важно держать предсказуемой: `streak.logic.ts`, `dailyBonus.logic.ts`, `level.ts`, `srs/`.
- **Внутренняя шина игровых событий** (`src/events/event-bus.ts`) с типизированными payload'ами.
- Подписчики вынесены в `src/events/subscribers.ts`: квесты, достижения, аудит-лог, пользовательские уведомления.
- `notice-buffer.ts` собирает последствия одного действия, чтобы показать **один** итоговый экран, а не 10 сообщений.

## 3. База данных (Prisma + PostgreSQL)

- 21 модель: `User`, `NotificationSettings`, `Word`, `UserWord`, `LearningSession`, `LearningAnswer`, `DailyActivity`, `EconomyTransaction`, `ShopItem`, `Purchase`, `InventoryItem`, `Quest`, `UserQuest`, `Achievement`, `UserAchievement`, `Reward`, `RewardPurchase`, `DailyBonusClaim`, `EasterEgg`, `UserEasterEgg`, `GameEventLog`.
- Enum'ы для статусов слов, типов упражнений, оценок, периодов квестов, типов товаров и контента.
- Индексы под реальные запросы: `userId + nextReviewAt`, `userId + localDay`, `isActive + sortOrder` и т.д.
- Уникальные ограничения как основа идемпотентности (см. п. 6).
- `prisma/seed.ts` наполняет **контентом** (25 слов, 8 квестов, 12 достижений, товары, награды, пасхалки) — без игровых констант.

## 4. Пользователь и таймзоны

- `/start` создаёт пользователя, повторный `/start` только обновляет профиль.
- Хранятся `timezone`, `language`, `learningLanguage`, `lastActivityDay` (локальный day key `YYYY-MM-DD`).
- `src/utils/time.ts`: day key, ISO-week key, границы локальных суток/недели, устойчивые к переходу на летнее время (двухпроходный расчёт offset).
- Ни одна ежедневная механика не считается по UTC.
- Настройки часового пояса доступны пользователю из меню.

## 5. Learning loop

- **Spaced repetition** вынесен в `src/services/srs/` за интерфейсом `SrsStrategy`.
  - Реализация по умолчанию — лестница интервалов `0 → 1 → 3 → 7 → 14 → 30 → 60` дней с SM-2-подобным ease factor.
  - Замена на SM-2/FSRS = одна новая реализация интерфейса, без правок вызывающего кода.
  - Статусы: `NEW → LEARNING → FAMILIAR → KNOWN → MASTERED`.
- **Типы упражнений** — реестр билдеров (`exercise.factory.ts`): `FLASHCARD`, `MULTIPLE_CHOICE`, `REVERSE`, `TRANSLATION`.
  - Новый тип добавляется через `registerExerciseBuilder()` без изменений в learning service.
  - Новые слова всегда показываются сначала карточкой.
- **Daily session**: превью (сколько карточек, ≈ минут, награды) → прохождение → единый экран итогов.
- Размер сессии, доля новых слов, оценки и награды — из конфига.
- Сохраняются `LearningSession` и `LearningAnswer` (включая `responseTimeMs`) для статистики.

## 6. Экономика и защита от эксплойтов

- Единственная точка изменения баланса — `economyService.applyLedger()`.
- Каждое изменение баланса создаёт запись `EconomyTransaction` (append-only ledger) с `balanceAfter`.
- Критический путь: `PostgreSQL транзакция → SELECT ... FOR UPDATE → проверка баланса → запись в ledger → обновление баланса`.
- Баланс не может уйти в минус (`InsufficientFundsError`).
- `rewardService.grant()` — единая точка выдачи наград (валюта, XP, щиты, предметы); ни один сервис не пишет в баланс/XP напрямую.
- **Идемпотентность** через уникальные ключи:
  - `EconomyTransaction.idempotencyKey` — все награды;
  - `DailyBonusClaim (userId, localDay)` — бонус нельзя забрать дважды;
  - `LearningAnswer (sessionId, position)` — ответ на карточку принимается один раз;
  - `UserAchievement (userId, achievementId)` — достижение выдаётся один раз;
  - `UserQuest (userId, questId, periodKey)` + условный `updateMany` при claim;
  - `Purchase.idempotencyKey`, `RewardPurchase.idempotencyKey`.
- Защита от двойного клика: per-user in-process мьютекс (`utils/mutex.ts`) перед покупками.
- `economyService.auditBalance()` сверяет кэшированный баланс с суммой ledger'а.

## 7. Streak

- Одно начисление в локальные сутки, независимо от числа тренировок.
- Обработаны: первый день, повтор в тот же день, пропуск, смена таймзоны, отрицательный gap (clock skew).
- **Streak Shield**: при пропуске автоматически тратится щит, серия сохраняется.
- Пропуск не обнуляет XP/слова — серия просто начинается с 1 (анти-фрустрация).
- Milestones (3/7/14/30/50/100/365) — конфигурируемые, награды через `RewardService`, с ключом идемпотентности.

## 8. XP, уровни, награды

- XP отделён от валюты.
- Уровень считается по таблице порогов (30 уровней + линейное продолжение), формула нигде не захардкожена в хендлерах.
- События `LEVEL_UP` с наградой за каждый уровень и отдельными milestone-наградами.
- Прогресс-бар уровня в профиле и главном меню.

## 9. Квесты

- Ежедневные и недельные; архитектура поддерживает `LONG_TERM`.
- Метрики: ответы, правильные ответы, выученные слова, сессии, XP, активные дни, бонусы.
- Набор квестов на период выбирается детерминированно (одинаковый весь период), с учётом веса квеста.
- Прогресс обновляется автоматически через подписчиков на события.
- Выполненные, но не забранные квесты **не сгорают** (анти-фрустрация).

## 10. Достижения

- Условия хранятся данными (`{ metric, threshold }`), 11 поддерживаемых метрик.
- Проверка при завершении сессии, обновлении streak, получении бонуса и при открытии экрана достижений.
- Защита от повторной выдачи на уровне БД.
- Поддержаны секретные достижения.

## 11. Магазин и персональные награды

- `ShopItem`: код, цена, тип, `metadata`, лимит на пользователя, склад, активность.
- Типы: `STREAK_SHIELD`, `XP_BOOST`, `COSMETIC`, `SPECIAL_REWARD`, `PERSONAL_REWARD` — эффект применяется данными, а не `if`-ами в UI.
- Понятное сообщение при нехватке валюты (сколько нужно / сколько есть).
- `Reward` — персональные награды администратора: текст, фото, видео, гиф, документ, аудио, голосовое, стикер.
- Купленные награды хранятся и открываются повторно из «Моих покупок».

## 12. Telegram UI

- Главное меню: Учиться / Задания / Бонус / Прогресс / Магазин / Достижения / Профиль / Настройки.
- Полностью на inline-клавиатурах, везде есть возврат в меню.
- Сообщения **редактируются**, а не отправляются заново (`render()`), чат не засоряется.
- Профиль и экран прогресса с текстовой визуализацией недели.
- Callback data содержит только действие и идентификатор; цены, награды и права читаются из БД.
- Длина callback data валидируется (лимит Telegram 64 байта).

## 13. Админка

- Доступ строго по `ADMIN_TELEGRAM_ID` из окружения.
- Разделы: слова, награды, товары, секреты (пасхалки), статистика, игроки.
- Пошаговые мастера создания с валидацией через Zod.
- Медиа принимается сообщением, сохраняется Telegram `file_id`.
- Команда `/fileid` для получения `file_id` любого медиа.
- Никаких конкретных наград/цен в коде — всё создаётся из бота.

## 14. Уведомления

- Планировщик с тиком раз в 5 минут.
- Напоминание не чаще одного раза в день, в окне ±10 минут от заданного локального времени.
- Не беспокоит тех, кто уже занимался сегодня.
- При блокировке бота (403) уведомления автоматически отключаются.
- Пользователь может выключить любые напоминания в настройках.

## 15. Надёжность и эксплуатация

- Глобальный `bot.catch` — Telegram и сетевые ошибки не роняют процесс.
- Пользователю показывается дружелюбное сообщение, стек-трейсы скрыты.
- Structured logging (pino) со скрытием токенов и секретов.
- Graceful shutdown по SIGINT/SIGTERM: остановка планировщика, бота, HTTP-сервера, отключение от БД.
- Обработчики `unhandledRejection` / `uncaughtException`.
- Health check `GET /health` с проверкой соединения с БД.
- Поддержаны оба режима: long polling (dev) и webhook с secret token (prod).

## 16. Пасхалки (персональный слой)

- Модели `EasterEgg` / `UserEasterEgg`.
- Триггеры: команда, фраза в сообщении, длина streak, уровень, календарная дата (например `02-14`).
- Контент любого поддерживаемого Telegram типа + необязательная награда.
- Повторяемые и одноразовые секреты, счётчик найденного в профиле.
- Обработчик подключён последним, чтобы не перехватывать обычные команды.
- Создаются из админки без деплоя.

## Что осталось за рамками MVP

- Упражнение `TRANSLATION` со свободным вводом текста (билдер готов, UI-ветка не подключена).
- Bulk-импорт слов из JSON/CSV (схема к этому готова).
- Лидерборды, коллекции, косметика, сезонные события — архитектура расширяема без рефакторинга.
